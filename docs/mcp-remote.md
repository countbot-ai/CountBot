# 远端 MCP 接入指南

通过「设置 → MCP」可以让 CountBot 连接远端 MCP Server，并将选定的工具提供给 AI。本文使用通用占位配置，说明当前源码中 MCP 管理面板的行为。端点、鉴权方式和工具名称应以你所用服务的文档为准；不同版本的桌面包可能与当前源码有所区别。

## 接入前准备

- 确认服务提供的是 **Streamable HTTP** 还是 **SSE** 端点，复制完整 URL，保留服务要求的路径和尾部斜杠。远端服务使用 HTTPS。
- 查清服务要求的请求头。`Authorization: Bearer …` 是一种常见方式，但不是所有 MCP 服务都使用它。
- 了解服务允许哪些操作、发送哪些数据、如何计费，以及如何撤销凭据。优先使用只授予所需权限的凭据。
- 确认 CountBot 的 Python 环境安装了项目依赖；出现 `mcp package not installed` 时，按根目录 README 的依赖安装步骤处理。

MCP 的全局开关默认关闭。开启后，已保存且启用的 Server 也可能开始连接；先检查已有配置。

## 添加与验证

1. 打开「设置 → MCP」，开启 MCP，再点「添加 Server」。
2. 填写不重复的 Server 名称，在「传输方式」中明确选择 **Streamable HTTP** 或 **SSE**。这两种方式不是可互换的选项；HTTP 端点也不需要填写 stdio 的启动命令。
3. 填入 URL，在「请求头」下点「添加请求头」，填写服务要求的头名和值。例如头名为 `Authorization`，值为 `Bearer ` 加上凭据；不要把凭据拼入 URL。
4. 在「只暴露这些工具」中填写需要使用的准确工具名，多个名称用逗号分隔。「开放资源读取」和「开放提示模板」可以保持关闭，直到确有需要。
5. 点「测试连接」，查看初始化与工具发现结果。成功消息中的名称可用于核对工具范围；填入占位工具名时，必须换成服务实际提供的名称。
6. 核对配置后点编辑器中的「保存配置」，再点「刷新」，确认 Server 显示「已连接」，并从工具数量或「状态」按钮查看工具列表。

测试连接会访问远端服务并发现工具；它不验证某个业务工具的完整执行，也不代表调用免费。在 MCP 已启用时，测试成功还可能触发实际连接和工具注册，所以测试前就应设置工具范围。

保存配置时，启用中的 MCP 会断开现有连接，再连接注册表中启用的服务。因此修改一个 Server 也可能让其他 MCP 连接重建；执行中的任务应先结束。

### JSON 编辑示例

在单个 Server 的编辑器里切换到「JSON」，可以填写以下配置。这里是**单个 Server 对象**，不是工具栏「导入配置」使用的 `mcpServers` 外层格式。下面的域名、凭据和工具名称仅为占位，不能直接连通：

```json
{
  "name": "remote-mcp",
  "transport": "streamable_http",
  "url": "https://mcp.example.com/mcp",
  "headers": {
    "Authorization": "Bearer REPLACE_WITH_YOUR_TOKEN"
  },
  "include_tools": ["read_document"],
  "exclude_tools": [],
  "enable_resources": false,
  "enable_prompts": false,
  "timeout": 30,
  "connect_timeout": 10
}
```

切回「图形」确认字段后保存。新建 Server 的 ID 由面板生成，编辑时沿用已有 ID。

「超时」是工具调用的等待时限，范围为 5–300 秒；「连接超时」范围为 5–60 秒。超时不证明远端操作没有发生，也不保证服务侧停止处理或计费。对有副作用的调用，先确认服务侧结果再决定是否重试。

## 请求头与凭据

请求头的值是**字面值**。在界面或 JSON 中填写 `${TOKEN}`、`$TOKEN` 或 `%TOKEN%`，CountBot 不会自动从环境变量替换它们；填写 stdio 的「环境变量」也不会给远端 HTTP 请求添加鉴权。

当前 MCP 配置会将 Header 值作为普通配置保存到本地数据库，编辑器可以显示这些值，MCP 导出文件也包含请求头。不要把真实凭据写进仓库、聊天内容、截图、Issue、日志附件或共享的导出文件；保护本地配置数据库及备份。不能将其他配置模块的密钥加密能力视为 MCP Header 已加密。

更换凭据时，编辑对应 Server 的请求头并保存，确认重连结果。若凭据泄漏，必须在服务侧撤销旧凭据；仅修改本地值不会让旧凭据失效。

## 选择工具范围

- 「只暴露这些工具」接受服务返回的原始工具名，也接受 CountBot 注册后的 `mcp_<server_id>_<tool_name>` 名称。面板工具列表展示的是注册后的名称，名称中的特殊字符可能被转换为下划线。
- `*` 表示允许全部工具。**空列表或清空输入框也会退回允许全部工具，不能用它来禁用工具。** 不想使用该 Server 时应停止或删除它，或关闭 MCP。
- 「排除这些工具」用于排除指定名称；不要把同一名称同时填进包含和排除列表。除 `*` 表示全部外，不要假设支持 `read_*` 等模式匹配。
- 工具名称填错可能导致连接正常但没有相应工具。不要为了排障直接改成 `*`；先对照测试发现的名称和已注册列表。
- 工具过滤只控制 CountBot 暴露的工具，不替代服务侧凭据权限。「开放资源读取」和「开放提示模板」是额外能力开关，不由工具名称列表限制。

工具栏支持导入、导出兼容 `mcpServers` 的 JSON，但导出不是全部高级字段的完整备份：显式传输方式和 `exclude_tools` 等字段不会全部保留。重新导入后，应再检查传输方式及工具范围，尤其不要因丢失排除项而放开额外工具。含凭据的配置不要导入未知来源，也不要共享导出文件。

## 停止、删除与清理

- **停止单个 Server**：点该行「停止」，关闭当前连接并移除相应运行时工具。该操作保留已保存配置，手动停止标记属于当前运行进程；保存配置、重新开启 MCP 或重启 CountBot 后，启用的配置可能再次连接。
- **关闭全部 MCP**：关闭面板顶部开关，保存全局关闭状态并断开连接；Server 配置仍保留。
- **删除 Server**：点「删除」并确认。面板会保存删除后的注册表；若 MCP 正启用，也会重新建立剩余服务的连接。确认操作成功后刷新，检查目标条目和工具已移除。

停止或删除本地配置不等于撤销服务侧凭据，也不保证远端任务已取消。删除配置不能安全擦除旧数据库页、历史备份或导出文件；不再使用服务时，另行撤销凭据并清理自己保留的敏感副本。

## 常见问题

| 现象 | 核对方法 |
| --- | --- |
| 验证失败或 URL 错误 | 确认名称、完整 HTTPS URL、传输方式、请求头和超时范围；SSE 与 Streamable HTTP 使用各自的端点 |
| 鉴权失败（例如 401/403） | 检查头名、Bearer 前缀（如服务要求）、凭据有效性和权限；确认没有把环境变量占位符当实际值，也没有发给错误的主机 |
| 已连接但找不到工具 | 核对服务发现结果与包含/排除列表，查看已注册工具；存在连接不保证所有工具都可用 |
| 测试成功，保存后仍未连接 | 确认保存成功、MCP 总开关开启、刷新后的状态；测试时的临时配置与保存的配置应一致 |
| 调用超时或连接中断 | 先判断服务侧操作是否发生，再检查网络和服务状态；对会写入或计费的操作不要盲目重试 |
| 停止后又连接 | 检查是否保存了注册表、重新开启 MCP 或重启应用；长期不用时关闭 MCP 或删除对应 Server |

排障时只分享脱敏后的错误与配置形状。连接测试、工具注册和业务调用是不同步骤；一次测试成功不能代替实际工具行为与权限检查。
