# 六、定时调度与心跳系统

定时调度系统让 CountBot 能够按时执行任务，心跳系统让 AI 能够主动关怀用户。

## 2、CronScheduler（智能调度器）

核心文件：`backend/modules/cron/scheduler.py`

### （1）核心设计理念：精确唤醒而非轮询

传统的 cron 实现通常每秒或每分钟检查一次是否有任务到期，这会浪费 CPU 资源。CountBot 的调度器采用**精确计算唤醒时间**的方式：

```python
# scheduler.py:124-160
def _arm_timer(self):
    """调度下一个定时器"""
    async def schedule_next():
        # 1. 获取最近的任务运行时间
        next_wake = await self._get_next_wake_time()

        if not next_wake:
            await asyncio.sleep(60)  # 没有任务，60秒后重新检查
            self._arm_timer()
            return

        # 2. 计算需要等待的精确时间
        now = _now_shanghai()
        delay = (next_wake - now).total_seconds()
        if delay < 0:
            delay = 0  # 已过期，立即执行

        # 3. 精确等待
        await asyncio.sleep(delay)

        # 4. 到点执行
        if self._running:
            await self._on_timer()

    self._timer_task = asyncio.create_task(schedule_next())
```

### （3）安全执行包装

```python
# scheduler.py:201-240
async def _execute_job_safe(self, job):
    """带信号量、超时和独立 session 的安全执行"""
    async with self._semaphore:          # 并发控制
        self._active_jobs.add(job.id)
        try:
            async with self.db_session_factory() as db:  # 独立数据库会话
                service = CronService(db)
                fresh_job = await service.get_job(job.id)  # 重新加载最新状态
                if fresh_job and fresh_job.enabled:
                    await asyncio.wait_for(     # 超时控制
                        self._execute_job(fresh_job, service),
                        timeout=self.job_timeout,
                    )
        except asyncio.TimeoutError:
            # 更新超时状态
            ...
        finally:
            self._active_jobs.discard(job.id)
```

关键点：
- 每个任务使用**独立的数据库会话**，避免事务冲突
- 执行前**重新加载任务**，获取最新状态（可能已被禁用）
- **信号量**限制并发数（默认最多 3 个任务同时执行）
- **超时控制**防止任务无限运行

### （4）防重复执行

```python
# scheduler.py:162-199
async def _on_timer(self):
    """定时器触发时"""
    due_jobs = await service.get_due_jobs()

    # 过滤掉正在执行的任务
    pending = [j for j in due_jobs if j.id not in self._active_jobs]
    if not pending:
        return
```

### （5）SQLite 并发锁处理

```python
# scheduler.py:300-313
async def _safe_commit(self, db):
    """带重试的安全 commit"""
    for attempt in range(MAX_COMMIT_RETRIES):  # 最多 3 次
        try:
            await db.commit()
            return
        except Exception as e:
            if "database is locked" in str(e).lower():
                wait = 0.5 * (attempt + 1)  # 0.5s → 1.0s → 1.5s
                await asyncio.sleep(wait)
            else:
                raise
```

## 3、CronExecutor（任务执行器）

核心文件：`backend/modules/cron/executor.py`

### （1）执行入口

```python
async def execute(self, job_id, message, channel, chat_id, deliver_response):
    # 1. 识别心跳任务
    if message == "__heartbeat__":
        greeting = await self.heartbeat_service.execute()
        if greeting and channel and chat_id:
            # 通过渠道发送问候语
            await self.channel_manager.send_message(OutboundMessage(...))
        return greeting

    # 2. 普通任务 → Agent 处理
    response = await self.agent.process_direct(
        content=message,
        session_id=f"cron:{job_id}",
    )

    # 3. 如果指定了渠道且需要投递响应
    if deliver_response and channel and chat_id and response:
        await self.channel_manager.send_message(OutboundMessage(...))

    return response
```

### （2）心跳任务与普通任务的区别

| | 心跳任务 | 普通任务 |
|---|---------|---------|
| 触发消息 | `__heartbeat__` | 任意文本 |
| 执行方式 | HeartbeatService.execute() | AgentLoop.process_direct() |
| 是否总是执行 | 否（有多重条件判断） | 是 |
| 是否使用工具 | 否（纯 LLM 生成） | 是 |

## 4、HeartbeatService（心跳服务）

核心文件：`backend/modules/agent/heartbeat.py`

### （1）主动问候的判断流程

```
execute() 入口
    │
    ├── 1. 免打扰时段检查
    │   └── 当前北京时间是否在 quiet_start ~ quiet_end 范围内？
    │       （默认 21:00 ~ 08:00 免打扰）
    │       → 是 → 跳过
    │
    ├── 2. 今日已达上限检查
    │   └── 今天已问候次数 >= max_greets_per_day？
    │       （默认每天最多 2 次）
    │       → 是 → 跳过
    │
    ├── 3. 用户空闲检测
    │   └── 查询所有会话中用户最近一条消息的时间
    │       空闲时间 < idle_threshold_hours？
    │       （默认 4 小时）
    │       → 不够空闲 → 跳过
    │
    ├── 4. 随机概率
    │   └── random.random() > 0.5？
    │       → 跳过（让问候时间分布更自然）
    │
    └── 5. 生成问候语
        └── 使用 LLM 生成个性化问候
```

### （3）免打扰时段（跨午夜支持）

```python
# heartbeat.py:73-83
def _is_quiet_hour(self, hour):
    if self.quiet_start <= self.quiet_end:
        # 不跨午夜：如 1:00-6:00
        return self.quiet_start <= hour < self.quiet_end
    else:
        # 跨午夜：如 22:00-8:00
        return hour >= self.quiet_start or hour < self.quiet_end
```

### （2）下次运行时间计算

使用 `croniter` 库解析 cron 表达式并计算：

```python
from croniter import croniter

def calculate_next_run(self, schedule, base_time=None):
    base = base_time or _now_shanghai()
    cron = croniter(schedule, base)
    return cron.get_next(datetime)
```

## 6、定时任务的完整生命周期

```
1. 用户创建任务（通过 API 或 AI 工具调用）
    │
    ▼
2. CronService.create_job() → 保存到数据库
    │
    ▼
3. CronScheduler.trigger_reschedule() → 重新计算所有任务时间
    │
    ▼
4. CronScheduler._arm_timer() → 设置精确定时器
    │
    ▼ asyncio.sleep(精确等待)
    │
    ▼
5. CronScheduler._on_timer() → 获取到期任务
    │
    ▼
6. CronScheduler._execute_job_safe() → 带并发控制和超时保护
    │
    ▼
7. CronExecutor.execute() → 区分心跳/普通任务
    │
    ├── 心跳 → HeartbeatService → 生成问候 → 渠道发送
    │
    └── 普通 → AgentLoop → 执行任务 → 渠道发送（如配置）
    │
    ▼
8. 更新任务状态（last_run, last_status, run_count, next_run）
    │
    ▼
9. CronScheduler._arm_timer() → 为下次执行设置定时器
```
