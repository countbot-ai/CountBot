# 二、应用启动与生命周期

## 1、启动入口

CountBot 提供三种启动方式，分别对应不同的使用场景。

### （1）生产启动 `start_app.py`

```
python start_app.py
```

- 运行 FastAPI 服务器（uvicorn）
- 2 秒后自动打开浏览器
- 显示本地和远程访问地址
- 不启用热重载

### （2）开发启动 `start_dev.py`

```
python start_dev.py
```

- 启用热重载（监视 `backend/` 目录）
- 开启调试日志
- 适合开发调试

### （3）桌面应用启动 `start_desktop.py`

```
python start_desktop.py
```

- 整合 FastAPI + pywebview
- 支持 Windows/macOS/Linux
- 可通过 PyInstaller 打包

## 2、FastAPI 应用初始化

核心文件：`backend/app.py`

### （1）应用创建

```python

app = FastAPI(
    title="CountBot Desktop API",
    description="CountBot backend API",
    version="0.1.0",
    lifespan=lifespan,  # ★ 生命周期管理函数
)
```

关键点：`lifespan` 参数指定了应用的启动和关闭逻辑，这是 FastAPI 推荐的生命周期管理方式。

### （2）中间件注册顺序

```python
# 1. CORS 中间件（最外层）
app.add_middleware(CORSMiddleware, allow_origins=["*"], ...)

# 2. 远程认证中间件
app.add_middleware(RemoteAuthMiddleware, get_password_hash_fn=get_password_hash)
```

中间件执行顺序是**后注册先执行**，所以实际请求处理顺序是：
```
请求 → RemoteAuthMiddleware（认证检查）→ CORSMiddleware → 路由处理
```

## 3、生命周期管理（Lifespan）

`lifespan` 函数是整个应用的核心启动逻辑，位于 `backend/app.py:122-321`。

### （1）启动阶段的完整流程

```
lifespan() 启动
    │
    ├── 1. 初始化数据库
    │   └── init_db() → 创建表 + 初始化性格数据
    │
    ├── 2. 加载配置
    │   └── config_loader.load() → 从 SQLite 读取配置
    │
    ├── 3. 创建共享组件 ★
    │   └── _create_shared_components(config)
    │       ├── LiteLLMProvider（LLM 提供商）
    │       ├── MemoryStore（记忆存储）
    │       ├── SkillsLoader（技能加载器）
    │       ├── ContextBuilder（上下文构建器）
    │       ├── SubagentManager（子代理管理器）
    │       └── ToolRegistry（工具注册表）
    │
    ├── 4. 创建消息系统
    │   ├── EnterpriseMessageQueue（消息队列）
    │   └── RateLimiter（限流器）
    │
    ├── 5. 创建消息处理器
    │   └── ChannelMessageHandler（频道消息处理器）
    │
    ├── 6. 创建渠道管理器
    │   └── ChannelManager → 初始化已启用的渠道
    │
    ├── 7. 初始化 OSS 上传器（可选）
    │
    ├── 8. 启动后台任务
    │   ├── channel_manager.start_all()（渠道连接）
    │   └── message_handler.start_processing()（消息消费）
    │
    ├── 9. 初始化定时任务系统
    │   ├── 创建 CronAgent（专用 Agent 循环）
    │   ├── 创建 CronExecutor + CronScheduler
    │   └── scheduler.start()
    │
    ├── 10. 注册心跳任务
    │   ├── HeartbeatService（心跳服务）
    │   └── ensure_heartbeat_job()（确保 cron job 存在）
    │
    └── 11. 注册退出清理
        └── atexit.register(cleanup_on_exit)
```

### （2）共享组件创建详解

`_create_shared_components()` 是最关键的初始化函数（`backend/app.py:17-119`），它创建了所有核心组件：

#### （2.1）Provider 创建

```python
# 从配置中获取 LLM 提供商信息
provider_id = config.model.provider          # 如 "zhipu"
provider_config = config.providers.get(provider_id)  # 获取对应配置
provider_meta = get_provider_metadata(provider_id)   # 获取元数据

# 创建 LiteLLM 提供商实例
provider = LiteLLMProvider(
    api_key=api_key,
    api_base=api_base,
    default_model=config.model.model,  # 如 "glm-4-flash"
    timeout=120.0,
    max_retries=3,
    provider_id=provider_id,
)
```

#### （2.2）工作区与记忆初始化

```python
# 工作区目录结构
workspace/
├── memory/
│   └── MEMORY.md        # 记忆文件
├── skills/              # 技能文件
└── ...                  # 其他工作文件
```

#### （2.3）ContextBuilder 组装

ContextBuilder 聚合了多个组件，负责构建发送给 LLM 的完整上下文：

```python
context_builder = ContextBuilder(
    workspace=workspace,     # 工作区路径
    memory=memory,           # 记忆存储
    skills=skills,           # 技能加载器
    persona_config=config.persona,  # 人设配置
)
```

#### （2.4）工具注册

```python
tool_registry = register_all_tools(
    workspace=workspace,
    command_timeout=config.security.command_timeout,
    max_output_length=config.security.max_output_length,
    allow_dangerous=not config.security.dangerous_commands_blocked,
    restrict_to_workspace=config.security.restrict_to_workspace,
    # ... 更多安全配置
```

### （3）关闭阶段

```python
# backend/app.py:317-321
```

## 4、WebSocket 端点

### （1）连接建立流程

```python
# backend/app.py:384-479
@app.websocket("/ws/chat")
async def websocket_endpoint(websocket: WebSocket):
    # 1. 安全验证
    #    - 获取客户端 IP（TCP 层）
    #    - 检测代理头
    #    - 本地连接 → 放行
    #    - 远程连接 → 验证 token

    # 2. 获取共享组件
    shared = websocket.app.state.shared

    # 3. 创建独立的工具注册表（会话隔离）
    tool_registry = register_all_tools(**shared["tool_params"], ...)

    # 4. 根据当前配置创建 Provider（支持动态切换）
    provider = LiteLLMProvider(...)

    # 5. 创建 Agent 循环
    agent_loop = AgentLoop(
        provider=provider,
        tools=tool_registry,
        context_builder=shared["context_builder"],  # 共享
        ...
    )

    # 6. 进入 WebSocket 事件循环
    await handle_websocket(websocket, agent_loop=agent_loop)
```

关键设计：
- **工具注册表是每连接独立的**（会话隔离，避免工具状态冲突）
- **ContextBuilder 是共享的**（保证所有连接使用一致的提示词）
- **Provider 按当前配置创建**（支持用户在前端切换模型后立即生效）

## 5、关键设计决策

### （1）为什么每个 WebSocket 连接需要独立的工具注册表？

工具注册表中的工具实例可能持有状态（如当前 session_id），如果多个连接共享同一个工具注册表，可能导致：
- 审计日志记录到错误的会话
- 工具执行结果发送到错误的连接

### （2）为什么 Provider 在 WebSocket 中重新创建？

用户可能在前端修改了模型配置（如切换到不同的 LLM 提供商），新的 WebSocket 连接应该使用最新配置。

### （3）为什么使用 asynccontextmanager 而不是 on_startup/on_shutdown？

FastAPI 推荐使用 `lifespan` 模式，因为：
- 组件的创建和销毁在同一个函数中，逻辑更清晰
- 通过 `yield` 分隔启动和关闭逻辑
- 组件的生命周期由 Python 上下文管理器自动管理
