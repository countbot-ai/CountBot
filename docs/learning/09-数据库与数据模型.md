# 九、数据库与数据模型

CountBot 使用 SQLite 作为数据库，通过 SQLAlchemy 2.0 异步 ORM 进行数据访问。

## 1、数据库架构概览

```
~/.countbot/data/countbot.db   (SQLite 数据库文件)
│
├── sessions              # 会话表
├── messages              # 消息表（与 sessions 一对多）
├── cron_jobs             # 定时任务表
├── settings              # 配置键值表
├── personalities         # 性格预设表
├── tasks                 # 任务表（未来扩展）
└── tool_conversations    # 工具对话记录表
```

## 2、数据库初始化

核心文件：`backend/database.py`

### （1）引擎创建

```python
# database.py
from backend.utils.paths import DATA_DIR

DATABASE_PATH = DATA_DIR / "countbot.db"
DATABASE_URL = f"sqlite+aiosqlite:///{DATABASE_PATH}"
SYNC_DATABASE_URL = f"sqlite:///{DATABASE_PATH}"

# 异步引擎（主要使用）
engine = create_async_engine(DATABASE_URL, echo=False, future=True)

# 同步引擎（用于非异步上下文，如性格加载）
sync_engine = create_engine(SYNC_DATABASE_URL, echo=False, future=True)
```

CountBot 同时维护异步和同步两个引擎：
- **异步引擎**：用于所有 API 请求、Agent 循环等异步代码
- **同步引擎**：用于少量需要同步访问的场景（如 ContextBuilder 中加载性格）

### （2）会话工厂

```python
# 异步会话工厂
AsyncSessionLocal = async_sessionmaker(engine, class_=AsyncSession, expire_on_commit=False)

# 同步会话工厂
SessionLocal = sessionmaker(sync_engine, expire_on_commit=False)
```

`expire_on_commit=False` 的意义：commit 后不自动过期属性，避免在 commit 后访问属性时触发额外的数据库查询。

### （3）数据库初始化函数

```python
# database.py:79-88
async def init_db():
    """初始化数据库"""
    # 导入所有模型（触发表定义注册）
    from backend.models import CronJob, Message, Personality, Session, Setting, Task, ToolConversation

    # 创建所有表
    async with engine.begin() as conn:
        await conn.run_sync(Base.metadata.create_all)

    # 初始化性格数据
    await init_personalities()
```

`create_all` 是幂等的：如果表已存在则跳过。

## 3、数据模型详解

### （1）Session（会话模型）

```python
class Session(Base):
    __tablename__ = "sessions"

    id: str                         # 主键（UUID）
    name: str                       # 会话名称（如 "telegram:12345"）
    created_at: datetime            # 创建时间
    updated_at: datetime            # 最后更新时间
    summary: str | None             # 会话总结（自动生成）
    summary_updated_at: datetime    # 总结更新时间
    last_summarized_msg_id: int     # 最后总结到的消息 ID
```

会话名称的命名规则：
- Web 会话：由前端生成的 UUID
- 渠道会话：`{channel}:{chat_id}`（如 `telegram:12345`）
- 定时任务会话：`cron:{job_id}`

### （2）Message（消息模型）

```python
class Message(Base):
    __tablename__ = "messages"

    id: int                   # 自增主键
    session_id: str           # 外键 → sessions.id
    role: str                 # "user" | "assistant" | "system"
    content: str              # 消息内容
    created_at: datetime      # 创建时间
```

索引：`idx_messages_session (session_id, created_at)` — 优化按会话查询历史消息。

### （3）CronJob（定时任务模型）

```python
class CronJob(Base):
    __tablename__ = "cron_jobs"

    id: str                   # 主键（UUID 或 "builtin:heartbeat"）
    name: str                 # 任务名称
    schedule: str             # Cron 表达式（如 "0 * * * *"）
    message: str              # 执行时发送的消息内容
    enabled: bool             # 是否启用
    channel: str | None       # 投递渠道
    chat_id: str | None       # 投递目标
    deliver_response: bool    # 是否投递 Agent 响应
    last_run: datetime | None # 最后运行时间
    next_run: datetime | None # 下次运行时间
    last_status: str | None   # 最后状态（"ok"/"error"/"skipped"）
    last_error: str | None    # 最后错误信息
    last_response: str | None # 最后响应（截取前 1000 字符）
    run_count: int            # 总运行次数
    error_count: int          # 总错误次数
    created_at: datetime      # 创建时间
    updated_at: datetime      # 更新时间
```

索引：
- `idx_cron_next_run (next_run, enabled)` — 优化获取到期任务
- `idx_cron_channel (channel, chat_id)` — 优化按渠道查询

### （4）Setting（配置模型）

```python
class Setting(Base):
    __tablename__ = "settings"

    key: str             # 主键（配置键，如 "model.provider"）
    value: str           # 配置值（JSON 序列化）
    updated_at: datetime # 更新时间
```

配置以 key-value 形式存储，value 通常是 JSON 字符串。

### （5）Personality（性格模型）

```python
class Personality(Base):
    __tablename__ = "personalities"

    id: str                # 主键（如 "grumpy", "gentle"）
    name: str              # 显示名称（如 "暴躁老哥"）
    description: str       # 性格描述
    traits: list[str]      # 性格特征列表（JSON 数组）
    speaking_style: str    # 说话风格
    icon: str              # 前端图标名
    is_builtin: bool       # 是否内置
    is_active: bool        # 是否激活
```

### （6）ToolConversation（工具对话记录）

记录每次工具调用的详细信息，用于前端展示和审计。

## 4、数据库访问模式

### （1）API 路由中的使用

```python
# 使用 FastAPI 的依赖注入
from backend.database import get_db

@router.get("/api/sessions")
async def list_sessions(db: AsyncSession = Depends(get_db)):
    result = await db.execute(select(Session).order_by(Session.updated_at.desc()))
    sessions = result.scalars().all()
    return sessions
```

### （2）频道处理器中的使用

```python
# 使用会话工厂手动管理
db_session_factory = get_db_session_factory()

async def _save_message(self, session_id, role, content):
    async with self.db_session_factory() as db:
        db.add(Message(session_id=session_id, role=role, content=content))
        await db.commit()
```

### （3）Cron 调度器中的使用

```python
# 每个任务使用独立的数据库会话
async def _execute_job_safe(self, job):
    async with self.db_session_factory() as db:
        service = CronService(db)
        fresh_job = await service.get_job(job.id)
        # ...
        await self._safe_commit(db)
```

独立会话避免了多个并发任务之间的事务冲突。

## 5、性格数据初始化

```python
# database.py:91-143
async def init_personalities():
    """初始化内置性格数据（表为空时执行）"""
    async with AsyncSessionLocal() as session:
        # 检查是否已有数据
        existing = await session.execute(select(Personality))
        if existing.scalars().first():
            return  # 已有数据，跳过

        # 从 personalities.py 导入预设数据
        from backend.modules.agent.personalities import PERSONALITY_PRESETS

        for pid, data in PERSONALITY_PRESETS.items():
            personality = Personality(
                id=pid,
                name=data["name"],
                description=data["description"],
                traits=data["traits"],
                speaking_style=data["speaking_style"],
                icon=icon_map.get(pid, "Smile"),
                is_builtin=True,
                is_active=True,
            )
            session.add(personality)
        await session.commit()
```

## 7、SQLite 注意事项

### （1）并发写入

SQLite 不支持并发写入，CountBot 通过以下方式处理：
- `_safe_commit()` 方法遇到 `database is locked` 时自动重试
- 重试间隔递增：0.5s → 1.0s → 1.5s

### （2）异步驱动

使用 `aiosqlite` 作为异步驱动，通过线程池实现非阻塞 I/O。
