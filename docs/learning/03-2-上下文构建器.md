# 三-2、上下文构建器

ContextBuilder 负责构建发送给 LLM 的系统提示词和完整消息列表。它决定了 AI "知道什么"和"怎么表现"。

核心文件：`backend/modules/agent/context.py`

## 1、ContextBuilder 的角色

在 Agent 主循环中，`process_message()` 调用 ContextBuilder 来构建消息列表，这是 LLM 接收到的全部信息：

```
AgentLoop.process_message()
    │
    └── context_builder.build_messages(history, current_message, media, channel)
        │
        ├── build_system_prompt()    → 系统提示词（AI 的身份和规则）
        ├── history                  → 历史对话消息
        └── current_message + media  → 当前用户消息（可能含图片）
```

## 2、系统提示词构建

### （1）build_system_prompt 方法

```python
# context.py:30-67
def build_system_prompt(self, skill_names=None):
    parts = []

    # 1. 核心身份（包含所有指导原则）
    parts.append(self._get_identity())

    # 2. 技能系统
    if self.skills:
        # 2.1 自动加载的技能（always=true）
        always_skills = self.skills.get_always_skills()
        if always_skills:
            always_content = self.skills.load_skills_for_context(always_skills)
            parts.append(f"# 已激活技能\n\n{always_content}")

        # 2.2 可用技能摘要（按需加载）
        skills_summary = self.skills.build_skills_summary()
        if skills_summary:
            parts.append(f"# 可用技能\n\n{skills_summary}\n\n**使用方法**: read_file(...)")

    system_prompt = "\n\n---\n\n".join(parts)
    return system_prompt
```

### （2）提示词的组成部分

系统提示词由三块内容用 `---` 分隔拼接而成：

| 部分 | 来源 | 说明 |
|------|------|------|
| 核心身份 | `_get_identity()` | AI 的基本信息、性格、行为规范 |
| 已激活技能 | `get_always_skills()` | 标记为 `always=true` 的技能，始终加载 |
| 可用技能摘要 | `build_skills_summary()` | 按需加载的技能列表，AI 需要时通过 `read_file` 获取详情 |

## 3、核心身份提示词

### （1）_get_identity 方法结构

`_get_identity()` 方法（context.py:107-194）生成的提示词包含以下部分：

```
# 核心身份
├── 基本信息（时间、环境、工作目录、用户称呼）
├── 性格设定（从数据库加载或硬编码降级）
├── 工具使用原则（静默执行、简要说明场景）
├── 文件操作规范（大文件分段、精确编辑）
├── 记忆系统（写入/搜索/读取规则）
├── 安全准则（最高优先级）
└── 工作原则与特殊说明
```

### （2）各部分的作用

- **基本信息**：让 AI 知道当前时间、运行环境、工作目录位置等
- **性格设定**：决定 AI 说话的风格和态度（见下方性格系统详解）
- **工具使用原则**：指导 AI 何时直接执行工具、何时先向用户说明
- **文件操作规范**：防止 AI 一次性读取过大的文件、确保编辑操作精确
- **记忆系统规则**：指导 AI 何时写入记忆、如何搜索和读取记忆
- **安全准则**：最高优先级的安全约束（不执行危险命令等）

## 4、性格加载机制

### （1）三级降级策略

```python
# context.py:69-105
def _get_personality_from_db(self, personality_id, custom_text=""):
    # 1. 自定义性格 → 直接使用文本
    if personality_id == "custom":
        return f"自定义性格: {custom_text.strip()}"

    # 2. 从数据库加载性格
    try:
        with SessionLocal() as session:
            personality = session.execute(
                select(Personality).where(Personality.id == personality_id)
            ).scalar_one_or_none()
            if personality:
                return f"性格: {personality.name}\n描述: {personality.description}\n..."
    except Exception:
        pass

    # 3. 降级到硬编码版本
    from backend.modules.agent.personalities import get_personality_prompt
    return get_personality_prompt(personality_id, custom_text)
```

这里体现了**降级策略**：

| 优先级 | 来源 | 适用场景 |
|--------|------|----------|
| 1 | 自定义文本 | 用户选择 `custom` 并输入自定义性格描述 |
| 2 | 数据库 | 正常情况，从 Personality 表读取 |
| 3 | 硬编码 | 数据库异常时，回退到代码中的预设 |

每个性格预设包含四个字段：

    "description": "嘴上不饶人但实际很靠谱的技术大佬",

## 5、消息列表构建

### （1）build_messages 方法

```python
# context.py:198-226
def build_messages(self, history, current_message, session_summary=None,
                   skill_names=None, media=None, channel=None, chat_id=None):
    messages = []

    # 1. 系统提示词
    system_prompt = self.build_system_prompt(skill_names)
    if session_summary:
        system_prompt += f"\n\n## Current Session Context\n{session_summary}"
    if channel and chat_id:
        system_prompt += f"\n\n## Current Session\nChannel: {channel}\nChat ID: {chat_id}"
    messages.append({"role": "system", "content": system_prompt})

    # 2. 历史消息
    messages.extend(history)

    # 3. 当前用户消息（可能含图片）
    user_content = self._build_user_content(current_message, media)
    messages.append({"role": "user", "content": user_content})

    return messages
```

### （2）消息列表结构

最终构建出的消息列表结构如下：

```python
[
    {"role": "system", "content": "系统提示词 + 会话摘要 + 渠道信息"},
    {"role": "user", "content": "历史消息1"},
    {"role": "assistant", "content": "历史回复1"},
    ...
    {"role": "user", "content": "当前消息（纯文本或含图片）"},
]
```

### （3）动态附加信息

注意 `build_messages` 会根据情况在系统提示词末尾追加：

- **session_summary**：如果有之前的对话总结，追加为 `## Current Session Context`。这是记忆系统总结后的压缩上下文
- **channel + chat_id**：标记当前消息来源渠道，让 AI 知道用户是从哪个平台发来的消息

## 6、多模态支持

### （1）_build_user_content 方法

```python
# context.py:228-256
def _build_user_content(self, text, media):
    if not media:
        return text  # 纯文本

    # 将图片编码为 base64
    images = []
    for path in media:
        mime, _ = mimetypes.guess_type(path)
        if mime and mime.startswith("image/"):
            b64 = base64.b64encode(Path(path).read_bytes()).decode()
            images.append({
                "type": "image_url",
                "image_url": {"url": f"data:{mime};base64,{b64}"}
            })

    # 返回多模态内容（OpenAI 格式）
    return images + [{"type": "text", "text": text}]
```

### （2）处理逻辑

- **无媒体**：直接返回纯文本字符串
- **有图片**：将图片文件读取为 base64 编码，与文本一起组成多模态消息数组
- 采用 **OpenAI 格式**的多模态消息结构，LiteLLM 会负责转换为各家 LLM 的对应格式
- 图片放在文本前面（`images + [text]`），这样 LLM 会先"看到"图片再读到文本

## 7、ContextBuilder 的组装

ContextBuilder 在应用启动时由 `_create_shared_components()` 创建：

```python
context_builder = ContextBuilder(
    workspace=workspace,     # 工作区路径
    memory=memory,           # 记忆存储
    skills=skills,           # 技能加载器
    persona_config=config.persona,  # 人设配置
)
```

作为**共享组件**，所有 WebSocket 连接和渠道处理器使用同一个 ContextBuilder 实例。这保证了所有连接使用一致的提示词和技能配置。
