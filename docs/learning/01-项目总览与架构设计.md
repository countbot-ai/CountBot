# 一、CountBot 项目总览与架构设计

## 1、项目简介

CountBot 是一个轻量级、可扩展的 AI Agent 框架，专为中文用户和国内 LLM 提供商优化。它实现了一个生产级的智能助手，具备记忆管理、多渠道支持和智能任务调度等核心能力。

### （1）核心定位

CountBot 不是一个简单的聊天机器人，而是一个完整的 **AI Agent 框架**。它的核心设计理念是：

- **Agent 而非 Chatbot**：不仅能对话，还能调用工具、执行命令、操作文件
- **多渠道统一**：一套代码同时服务 Web、飞书、钉钉、QQ、Telegram 等平台
- **记忆持久化**：不仅记住当前对话，还能跨会话记忆用户偏好和重要信息
- **主动关怀**：通过心跳系统主动问候用户，而不是被动等待指令

### （2）技术栈概览

### （2）核心设计模式

#### （2.1）共享组件模式

这是 CountBot 最重要的设计决策之一。WebSocket 和渠道处理器共享同一套组件：

```python
# backend/app.py 中的 _create_shared_components()
shared = {
    "provider": provider,          # LLM 提供商（共享实例）
    "context_builder": context_builder,  # 上下文构建器（共享）
    "tool_registry": tool_registry,      # 工具注册表（每连接独立）
    "subagent_manager": subagent_manager, # 子代理管理器（共享）
    "memory": memory,                     # 记忆存储（共享）
    "skills": skills,                     # 技能加载器（共享）
}
```

这样做的好处：
- 所有渠道和 Web UI 使用完全一致的提示词、技能和工具
- 避免重复创建 LLM provider 实例，节约 API 配额
- 记忆和技能跨渠道共享

#### （2.2）依赖注入模式

组件在启动时创建，通过构造函数注入到需要它们的模块中：

```
app.py (lifespan)
  ├── 创建 Provider → 注入到 AgentLoop、HeartbeatService
  ├── 创建 ContextBuilder → 注入到 AgentLoop、ChannelMessageHandler
  ├── 创建 ToolRegistry → 注入到 AgentLoop
  └── 创建 ChannelManager → 注入到 ChannelMessageHandler
```

#### （2.3）策略模式

- `BaseChannel` 抽象基类定义统一接口，每个渠道实现不同的连接策略
- `Tool` 抽象基类定义工具接口，每个工具实现不同的执行逻辑
- 性格系统通过选择不同预设来改变 AI 的行为策略

#### （2.4）观察者模式

- 渠道通过回调函数将入站消息传递给消息队列
- WebSocket 连接管理器维护会话到连接的映射，支持按会话推送

## 4、核心数据流

### （1）用户消息处理全流程

```
用户输入（Web/飞书/钉钉/Telegram/QQ）
    │
    ▼
┌──────────────────────────────┐
│ 接入层：渠道接收 / WebSocket  │
└──────────┬───────────────────┘
           │
           ▼
┌──────────────────────────────┐
│ 消息队列：优先级排序 + 去重    │
└──────────┬───────────────────┘
           │
           ▼
┌──────────────────────────────┐
│ 消息处理器：命令识别 + 限流    │
│ (/new, /help, /stop 等命令)  │
└──────────┬───────────────────┘
           │ 非命令消息
           ▼
┌──────────────────────────────┐
│ 会话管理：获取/创建会话        │
│ 加载历史消息                  │
└──────────┬───────────────────┘
           │
           ▼
┌──────────────────────────────────────────────────────┐
│              Agent Loop (ReAct 循环)                   │
│                                                       │
│  1. ContextBuilder.build_system_prompt()              │
│     ├─ 核心身份 + 性格设定                             │
│     ├─ 已激活技能                                      │
│     └─ 可用技能摘要                                    │
│                                                       │
│  2. ContextBuilder.build_messages()                   │
│     ├─ system prompt                                  │
│     ├─ 历史消息                                       │
│     └─ 当前用户消息                                    │
│                                                       │
│  3. LiteLLMProvider.chat_stream() → 调用 LLM          │
│                                                       │
│  4. 解析响应                                           │
│     ├─ 有文本内容 → 流式输出给用户                      │
│     └─ 有工具调用 → 执行工具 → 将结果加入消息 → 回到 3  │
│                                                       │
│  5. 循环直到：                                         │
│     ├─ LLM 不再调用工具（正常结束）                      │
│     ├─ 达到最大迭代次数                                 │
│     └─ 用户取消                                        │
└──────────────────────────────┬────────────────────────┘
                               │
                               ▼
┌──────────────────────────────┐
│ 响应输出：                    │
│ Web → WebSocket 流式推送      │
│ 渠道 → 出站消息队列 → 渠道发送 │
└──────────────────────────────┘
```

### （2）定时任务执行流程

```
CronScheduler 计算最近的任务时间
    │
    ▼ asyncio.sleep(精确等待)
    │
    ▼
CronScheduler._on_timer() 触发
    │
    ▼ 获取所有到期任务
    │
    ▼ 通过 Semaphore 控制并发（最多 3 个）
    │
    ▼
CronExecutor.execute()
    ├── 心跳任务 → HeartbeatService.execute() → 生成问候语
    └── 普通任务 → AgentLoop.process_direct() → Agent 处理
    │
    ▼ 如果任务指定了渠道
    │
    ▼
ChannelManager.send_message() → 发送到指定渠道
```
